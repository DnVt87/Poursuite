# poursuite/probes/

Diagnostic tools that verify external-data-source claims used by Poursuite.
Read-only investigations — they hit external APIs and write artifacts to disk;
they never modify Poursuite's databases or scraper outputs.

## Read PROBE_FINDINGS first

Before running anything here, read [`PROBE_FINDINGS.md`](../../PROBE_FINDINGS.md)
in the project root. It documents what's already known about DataJud and
Receita CNPJ, and lists the empirical questions these probes try to answer
(§1.7 and §2.8). Each probe report references those sections directly.

## Layout

| File | Purpose |
|---|---|
| `datajud.py` | DataJud public-API probe + 5 Challenge Experiments |
| `receita.py` | Receita CNPJ schema-check (no download); sample download stubbed |
| `tpu.py` | Embedded TPU code subset + penhora/citação family detectors |
| `cli.py` / `__main__.py` | argparse entry point |
| `sample_processes.yaml` | Default 6 sample TJSP process numbers |
| `cnpj_layout.txt` | Schema baseline for Receita; replace with PDF transcription to detect drift |

## Running

```bash
# DataJud — all 6 default samples + 5 Challenge Experiments
python -m poursuite.probes datajud

# DataJud — single process
python -m poursuite.probes datajud --process 1018045-50.2015.8.26.0506

# DataJud — custom samples file
python -m poursuite.probes datajud --processes path/to/other.yaml

# DataJud — per-process probe only (no experiments)
python -m poursuite.probes datajud --skip-experiments

# Receita — schema check (no download, no third-party deps)
python -m poursuite.probes receita --schema-check

# Receita — bulk sample (NOT YET WIRED; prints help and exits non-zero)
python -m poursuite.probes receita --sample

# Consolidated report combining the most recent runs
python -m poursuite.probes report
```

## Outputs

All runs write to `<POURSUITE_LOG_DIR>/probes/` (default: `C:/Poursuite/Logs/probes/`):

```
probes/
├── datajud_<UTC-iso>/
│   ├── sample_00_digits_match.json     ← raw response per query variant
│   ├── sample_00_formatted_match.json
│   ├── exp1_*.json ... exp5_*.json     ← raw experiment responses
│   ├── samples_summary.json            ← parsed structured summary
│   ├── experiments_summary.json
│   └── datajud_report.md               ← human-readable report
├── receita_<UTC-iso>/
│   └── schema_diff_report.md
└── latest_report.md                    ← regenerated by `report` command
```

## DataJud API key

The probe reads `POURSUITE_DATAJUD_API_KEY` if set; otherwise falls back to
the public-wiki value from `PROBE_FINDINGS.md` §1.2. CNJ rotates this without
notice — if the probe gets HTTP 401/403 across the board, refresh the wiki
value at <https://datajud-wiki.cnj.jus.br/api-publica/acesso/>.

## Updating cnpj_layout.txt for real drift detection

The bundled `cnpj_layout.txt` mirrors `PROBE_FINDINGS.md` §2.4, so a fresh
schema-check reports ✓ across the board (a useful baseline, not real drift
detection). To do a meaningful check:

1. Fetch the latest `cnpj-metadados.pdf` from the Receita Federal
   "dados públicos CNPJ" page.
2. Replace the column lists in `cnpj_layout.txt` with a fresh transcription.
3. Re-run `python -m poursuite.probes receita --schema-check`.
4. Anything `⚠ missing` or `⚠ extra` is real drift between the PDF and
   `PROBE_FINDINGS.md` §2.4.

## What this is not

- Not a feature: nothing here is imported by `poursuite.api`, `poursuite.db`,
  or `poursuite.scraper`.
- Not a bulk Receita downloader (yet — `receita --sample` is intentionally
  stubbed; integration with `rictom/cnpj-sqlite` is gated behind a separate
  vendoring + license review pass).
- Not a continuous monitor — run on demand, not on a cron.
